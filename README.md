# Group1_TR_43 — EventOrganizer v2.0.0

Виконано лабораторні роботи №1–7 (Спринти 1–3). Поточна версія — **v2.0.0**.

Командний репозиторій першої групи ТР-43 для лабораторних робіт з ТРПЗ.  
Продукт: веб-застосунок для спільної організації подій та обліку витрат із контролем бюджету, фільтрацією заходів і автоматичним розрахунком переказів між учасниками.

## Що реалізовано у v2.0.0

- **Автентифікація користувачів (`FR-01`, `FR-02`):** реєстрація з гешуванням пароля та вхід до системи.
- **Управління подіями (`FR-03` – `FR-08`, `FR-13` – `FR-15`):** створення, редагування, закриття та скасування події, приєднання учасників за кодом запрошення.
- **Пошук і фільтрація подій (`FR-18` / `US-02`):** фільтрація списку заходів за статусом (`Created`, `Closed`, `Cancelled`) та пошук за частиною назви без урахування регістру.
- **Облік витрат, контроль бюджету та транзакції (`FR-09` – `FR-12`, `FR-16`, `FR-17` / `US-03`):**
  - необов'язковий ліміт бюджету події (`BudgetLimit`);
  - попередження при використанні `80%–100%` бюджету та відмова (`409 Conflict`) при перевищенні `> 100%`;
  - атомарне збереження витрати та її часток розподілу в одній транзакції SQLite.
- **План взаєморозрахунків (`FR-19` / `US-04` / `UC-12`):** автоматичний розрахунок мінімального переліку переказів («Хто кому скільки переказує») із точністю до `0,01 грн`.
- **Багатосторінковий веб-інтерфейс та архітектура:** Razor Pages (`/Account/Login`, `/Account/Register`, `/Index`, `/Events/Details`) взаємодіють із REST API через клієнтський фасад `IEventOrganizerApiFacade` (шаблон GoF `Facade`).

Повна відповідність вимог коду й тестам наведена в [docs/traceability.md](docs/traceability.md).

## Персистентне зберігання даних (SQLite + EF Core)

Починаючи зі Спринту 1 (`v1.1.0`), усі акаунти, події, учасники, витрати та частки зберігаються у реляційній базі даних **SQLite** через **Entity Framework Core**. Міграції застосовуються автоматично під час запуску сервера.

За потреби вручну застосувати міграції можна командою:
```bash
dotnet ef database update --project src/EventOrganizer.Api
```

## Покроковий запуск із вихідного коду

1. **Клонуйте репозиторій та зберіть рішення:**
   ```bash
   git clone https://github.com/Fidloc/Group1_TR_43.git
   cd Group1_TR_43
   dotnet build
   ```

2. **Запустіть усі автоматизовані тести (очікується 156/156 успішних тестів):**
   ```bash
   dotnet test
   ```

3. **Запустіть веб-сервер та клієнтський інтерфейс:**
   ```bash
   dotnet run --project src/EventOrganizer.Api --launch-profile http
   ```
   - Веб-інтерфейс доступний у браузері за адресою: `http://localhost:5076/`
   - Перевірка стану API (Healthcheck): `http://localhost:5076/health` → `{"status":"ok"}`
