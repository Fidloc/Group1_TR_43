## 1. Планування спринту

### 1.1. Product Goal та мета Sprint 3
* **Product Goal:** створити надійний, зручний та інтуїтивний веб-застосунок для спільної організації заходів із прозорим фінансовим обліком, контролем бюджету та автоматичним взаєморозрахунком між учасниками.
* **Sprint Goal:** усунути дублювання HTTP-логіки та сильне зчеплення сторінок Razor Pages із `HttpClient` / `JsonElement` шляхом впровадження структурного шаблону GoF **«Фасад»** зі збереженням усієї наявної поведінки, реалізувати нову користувацьку операцію **`US-04` / `UC-12` «План взаєморозрахунків (Хто кому скільки переказує)»** поверх оновленої архітектури, оновити модель реалізації та документацію й випустити реліз **`v2.0.0`**.

### 1.2. Картка задачі рефакторингу

* **Початковий стан коду:** класи сторінок `ApiPageModel.cs`, `Login.cshtml.cs`, `Register.cshtml.cs`, `Index.cshtml.cs` та `Details.cshtml.cs` містили `code smell` — дублювання створення `HttpClient` у понад 15 місцях, ручне склеювання URL/query-параметрів і парсинг JSON (`JsonElement` / `ReadApiErrorAsync`), а `DetailsModel.LoadEventDataAsync` самостійно виконував 5 послідовних HTTP-запитів до API.
* **Обраний шаблон проєктування GoF:** **фасад** — інтерфейс `IEventOrganizerApiFacade` та клас `EventOrganizerApiFacade(HttpClient)`.
* **Що змінилося в структурі:** усі маршрути `/api/...`, серіалізація запитів та обробка помилок HTTP зосереджені в `EventOrganizerApiFacade`; класи `PageModel` залежать лише від інтерфейсу `IEventOrganizerApiFacade`, отриманого через DI.
* **Спосіб перевірки збереження поведінки:**
  1. Перед перенесенням сторінок створено захисну сітку тестів `WebApiFacadeTests.cs` із використанням тестового двійника `FakeHttpHandler : HttpMessageHandler` (перевірка HTTP-методів, шляхів, query-параметрів, JSON-тіла запитів, успішних відповідей і кодів помилок `400`/`401`/`403`/`409` без запуску сервера).
  2. Рефакторинг сторінок виконано **окремим комітом** до додавання нової функціональності.
  3. Усі **156 автоматизованих тестів** проходять успішно без жодної регресії попереднього функціоналу.

### 1.3. Нова користувацька історія `US-04` / `UC-12`

* **Ідентифікатор та назва:** `US-04` (`UC-12`) — «План взаєморозрахунків (Хто кому скільки переказує)» (`3 SP`).
* **Формулювання:**  
  *«Як учасник або Організатор події, я хочу бачити готовий перелік переказів між учасниками («Хто → Кому: сума»), обчислений на основі їхніх балансів, щоб швидко закрити спільні витрати без ручних підрахунків».*
* **Перевірка за критеріями INVEST:**
  * **Independent:** обчислюється на льоту з наявних балансів (`BalanceDto[]`) без зміни схеми бази даних і без міграцій.
  * **Negotiable:** алгоритм мінімізації кількості переказів та формат відображення у UI узгоджені командою за принципом Contract-First.
  * **Valuable:** перетворює чисті сальдо учасників (`UC-06`) на конкретні інструкції для грошових переказів.
  * **Estimable:** оцінено командою у `3 SP` (чиста функція `CalculateSettlements`, ендпоінт `GET .../settlements`, метод фасаду `GetSettlementsAsync` та блок у UI).
  * **Small:** повністю реалізовано, протестовано та інтегровано в межах Спринту 3.
  * **Testable:** покрито модульними тестами `ExpenseCalculator.CalculateSettlements`, інтеграційними тестами `ExpenseService.GetSettlementsAsync` на `SQLite :memory:` (`SettlementTests.cs`) та тестами клієнта через `FakeHttpHandler` (`WebApiFacadeTests.cs`).
* **Критерії приймання (`AC-19`):**
  * **AC-19.1:** запит `GET /api/events/{eventId}/settlements` для існуючої події повертає `200 OK` та масив об'єктів `SettlementTransferDto` (`FromUserName`, `ToUserName`, `Amount`), де сума всіх переказів кожного боржника дорівнює модулю його від'ємного балансу, а сума отриманих переказів кожного кредитора — його додатному балансу з точністю до `0,01 грн`.
  * **AC-19.2:** якщо всі баланси дорівнюють `0`, система повертає порожній список, а веб-інтерфейс відображає статус *«Усі розрахунки закрито — боргів немає»*.
  * **AC-19.3:** при передачі `eventId <= 0` API повертає `400 Bad Request` (`invalid_request`), а для неіснуючої події — `404 Not Found` (`event_not_found`).
