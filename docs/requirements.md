## 1. Межі V1

| Входить до v1.0 | Не входить до v1.0 (відкладено на майбутні версії) |
|---|---|
| Реєстрація та вхід користувача | Голосування за дату або місце проведення |
| Створення події | Автоматичні нагадування про подію та оплату |
| Перегляд і редагування події | Чек-лист необхідних речей |
| Додавання учасників | Розширена статистика та аналітика проведених заходів |
| Облік спільних витрат і розподіл між учасниками | — |

## 2. Функціональні вимоги FR

| ID | Вимога | Критерій приймання |
|---|---|---|
| **FR-01** | Система повинна дозволяти користувачеві створити акаунт та увійти до системи. | **AC-01**: Після реєстрації з коректними даними користувач може увійти й бачить свої події. |
| **FR-02** | Система повинна відхиляти реєстрацію з email, що вже використовується, та вхід з невірними даними. | **AC-02**: Акаунт не створюється чи вхід не виконується, система повідомляє причину. |
| **FR-03** | Система повинна дозволяти авторизованому користувачеві створити подію з назвою, датою, місцем та описом; створювач стає Організатором. | **AC-03**: Після введення коректних даних подія збережена й відображається у списку подій. |
| **FR-04** | Система повинна відхиляти створення або збереження змін події без назви або без дати, а також з датою в минулому. | **AC-04**: Подію не створено чи зміни не збережено, система повідомляє причину. |
| **FR-05** | Система повинна дозволяти Організатору та Учасникам переглядати інформацію про подію. | **AC-05**: Сторінка події показує всю інформацію про неї. |
| **FR-06** | Система повинна дозволяти лише Організатору редагувати дані події. | **AC-06**: Організатор змінює поле, і воно оновлюється. Учаснику редагування недоступне. |
| **FR-07** | Система повинна дозволяти авторизованому користувачеві приєднатися до події як Учасник за посиланням-запрошенням. | **AC-07**: Користувач з'являється в списку учасників події. |
| **FR-08** | Система повинна показувати список учасників події. | **AC-08**: Список збігається з фактичним складом учасників. |
| **FR-09** | Система повинна дозволяти Учаснику зареєструвати спільну витрату: хто заплатив, сума, опис. | **AC-09**: Витрата збережена й видна в обліку події. |
| **FR-10** | Система повинна відхиляти витрату з сумою ≤ 0 або нечисловою. | **AC-10**: Витрата не зберігається, система повідомляє причину. |
| **FR-11** | Система повинна розподіляти витрату порівну між усіма учасниками, яких обере Організатор як залучених до цієї витрати. | **AC-11**: Сума часток дорівнює сумі витрати. |
| **FR-12** | Система повинна показувати кожному Учаснику, скільки він винен або йому винні. | **AC-12**: Баланси узгоджуються з зареєстрованими витратами. |

## 3. Нефункціональні вимоги (NFR)

| ID | Характеристика якості | Вимога | Метод перевірки |
|---|---|---|---|
| **NFR-01** | Продуктивність | Сервер відповідає на запит користувача не пізніше ніж за 1 с. | За допомогою DevTools / навантажувальних тестів. |
| **NFR-02** | Точність обчислень | Сума часток розподілу витрати збігається із сумою витрати з точністю до 0,01 грн незалежно від кількості обраних учасників. | Модульні тести на граничних випадках (100 грн на 3-х, 10 грн на 7-х, 0,01 грн на 2-х). |
| **NFR-03** | Зручність (Usability) | Новий користувач створює подію не більше ніж за 5 кроків від головної сторінки без додаткової інструкції. | Спостереження за 3 тестовими користувачами. |
| **NFR-04** | Сумісність | Усі функції v1.0 коректно працюють в актуальних Chrome, Firefox та Edge на ширині екрана від 360 px. | Ручна перевірка сценаріїв у трьох браузерах та адаптивному режимі. |
| **NFR-05** | Безпека | Паролі не зберігаються у відкритому вигляді (використовується гешування); дані події доступні лише її учасникам. | Огляд схеми бази даних; спроба несанкціонованого доступу за прямим URL. |
| **NFR-06** | Надійність | Дані акаунтів, подій і витрат зберігаються та не втрачаються після перезапуску сервера застосунку. | Створення даних, перезапуск контейнера/сервісу, звірка даних. |
| **NFR-07** | Розгортання | Застосунок успішно збирається та запускається однією командою (`docker compose up`) за інструкцією. | Запуск на чистій віртуальній машині або середовищі. |
