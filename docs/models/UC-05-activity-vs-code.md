# UC-05: порівняння діаграми діяльності з реалізацією v1.0

Діаграма діяльності: [model/activity-uc-05.md](../../model/activity-uc-05.md). Код: `ExpenseRegistration.cs`, маршрут `POST /api/events/{eventId}/expenses` у Program.cs, клієнт `ExpenseActions.cs`.

| Елемент діаграми | Як зроблено в коді | Висновок |
|---|---|---|
| Кроки 1–4: відкрити подію, ввести суму, опис, платника | Клієнт питає ID події, ID користувача, ID платника, суму й опис; на веб-сторінці користувач береться з входу | Відповідає (у v1.0 консольний клієнт, тому «сторінка» — це введення ID події) |
| Рішення «Подія у стані Створена?», A3 | Сервер повертає 409 `event_not_active` | Відповідає. Але в діаграмі стан перевіряється на самому початку, а в коді — вже після надсилання запиту, бо стан знає тільки сервер. Результат той самий: витрата не зберігається |
| Рішення «Підтвердити чи скасувати?», A2 | Порожня сума в клієнті = скасування, запит не надсилається | Відповідає (додано в клієнт після звірки з діаграмою) |
| Рішення «Сума — число і > 0?», A1 повертає до введення | Сервер повертає 400 `invalid_amount`, клієнт просить ввести суму ще раз | Відповідає (повернення до введення додано в клієнт після звірки) |
| Кроки 7–8: зберегти й показати | `expenses.Add`, 201; клієнт робить GET і показує облік події | Відповідає |
| Передумова «користувач — Організатор події» (FR-09) | Сервер перевіряє роль і повертає 403 `forbidden_not_organizer`, на сайті без входу — «Спочатку увійдіть у систему» | Відповідає. Перевірку додано в ЛР №4: спочатку код пускав будь-кого, хоча FR-09 дозволяє вносити витрату лише Організатору |

## Чого немає на діаграмі, але є в коді

- Сума з більш ніж 2 знаками після коми теж некоректна (`invalid_amount`), бо частки рахуються до 0,01 грн (NFR-02).
- 404 `event_not_found`, якщо події немає, і 404 `participant_not_found`, якщо платник не з цієї події.
- 400 `invalid_request`, якщо в запиті немає ID користувача або платника.

Це технічні перевірки на рівні API. На діаграмі діяльності їх немає, бо користувач на сторінці події не може вибрати неіснуючу подію чи чужого учасника.
